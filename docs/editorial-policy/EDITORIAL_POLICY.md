# 編集方針

## 1. 目的
IT System Atlas は、ITシステムの**存在・役割・規模・関係**を概要レベルで整理し、学生がIT産業の全体像を理解できるようにする公開アトラスです。技術解説サイト、製品比較サイト、求人サイトではありません。

## 2. 掲載範囲
| 掲載する | 掲載しない |
|---|---|
| 名称、概要（100〜300字）、用途、分野、利用者 | 詳細な業務処理・業務ロジック・業務マニュアル |
| 規模の目安（P区分・U区分）と、出典付きの参考値 | 非公開のシステム構成・設計仕様 |
| 関係するシステム | セキュリティ上の内部情報 |
| 公開資料・公式サイトへの出典 | 非公開の契約・開発実績、機密情報、個人情報 |

## 3. 規模情報
- 規模の目安は編集部の判断であり、「目安」と明示する。
- 数値の参考値は、出典・対象範囲・時点・測定対象（開発規模か稼働規模か）が確認できたものだけを掲載する。
- 根拠の種類（公表値／報道値／統計値／試算）を区別して表示する。教育用の試算には計算式を付ける。
- 出典のない数値は掲載しない。数値が公表されていない場合は「未公表」とする。

## 4. 実名事例ポリシー
1. 掲載根拠は、企業の公式開示（決算・IR・プレスリリース）、公的機関の資料、判決、主要報道に限る。
2. 「失敗した」「原因は〜」「経営が傾いた」など、出典に書かれていない評価・推測・断定を書かない。出典の記述の範囲で、日付・数値・事実のみを記載する。
3. 報道値は「報道値」と表示し、公式資料が見つかれば差し替える。
4. 掲載された企業・団体からの訂正申請には優先的に対応する。

## 5. 確認と公開
1. 追加・訂正は Pull Request または Issue で受け付け、`npm run check`（機械検査）を通す。
2. メンテナー（または、このリポジトリを授業で使う学校・団体の担当者）が内容を確かめ、`editorial.status` を `reviewed` にする。
3. `draft`（下書き）のカードも既定ではサイトに表示し、「下書き」と明示する。確認済みのカードだけで配布したい場合は `ATLAS_MODE=reviewed npm run build` で生成する。
4. 確認済みは、すべての専門分野の技術的な正確性を保証するものではない。授業では担当の先生が内容を確かめて使う。

## 6. 訂正・削除
- 誰でも Issue「訂正の申請」から申請できる。
- 権利者からの削除要請、個人情報・機密情報の掲載が判明した場合は、`editorial.status` を `withdrawn` にしてサイトから外す。
- すべての変更は Git の履歴として残る。
